1. ABSTRACT
============================================================
Wonderlove is a full-stack AI-powered travel planner that produces personalized multi-day
itineraries and aggregates transport, accommodation, and dining options into a single,
cohesive experience. The frontend is built with React and TypeScript, while the backend
uses Node.js/Express with MongoDB for persistence. Google Generative AI (Gemini) provides
structured itineraries in JSON that the application validates, corrects for day count, and
presents in a maps-enhanced UI. Authentication is handled via JWT tokens.

Citations: Gemini [1], React [2], Express [3], Mongoose/MongoDB [4], Google Maps [5], JWT [6].

============================================================
2. INTRODUCTION
============================================================
Travel planning typically requires time-consuming research across multiple sources, often
resulting in generic or impractical agendas. Wonderlove aims to reduce that friction by
leveraging AI to produce locally relevant, realistic daily plans with specific venues,
timings, and estimated costs, while allowing travelers to customize selections and manage a
cart for potential bookings.

============================================================
3. PROBLEM STATEMENT & OBJECTIVES
============================================================
Problem:
- Planning is fragmented (many tabs, apps, and spreadsheets), and results rarely reflect
  travelers’ unique interests, budgets, and constraints.

Objectives:
- Provide AI-generated itineraries that read like advice from a local expert, with
  realistic logistics and costs.
- Consolidate discovery of transport, hotels, and restaurants into one workflow.
- Deliver a polished, responsive UI with secure authentication and persistent state.

============================================================
4. SYSTEM OVERVIEW
============================================================
The system comprises:
- A React + TypeScript frontend (Vite) for user interaction, trip creation, itinerary
  viewing, maps visualization, and cart management.
- A Node.js/Express backend with REST endpoints for auth, trips, itineraries, cart, and
  options. Mongoose models manage MongoDB persistence.
- An AI service wrapping Google Generative AI (Gemini) prompts, response parsing, schema
  validation, and day-count correction.

============================================================
5. KEY FEATURES
============================================================
- Intelligent Itinerary Generation: Multi-day plans with morning/afternoon/evening segments,
  activity details, timing, estimated cost, and local tips.
- Trip Management: Create, edit, view trips; attach and render itineraries.
- Options Explorer: Surface transport, accommodation, and dining options and add to cart.
- Maps Integration: Visualize locations and overviews via Google Maps.
- Secure Authentication: JWT-based signup/login and token management.
- Premium UX: Responsive design and clean, modern UI components.

============================================================
6. USER PERSONAS & STORIES
============================================================
Personas:
- Busy Professional: Wants efficient planning, reliable schedules, upscale options.
- Backpacker: Prefers budget, adventurous activities, and local cuisine.
- Family Planner: Seeks kid-friendly activities, safe areas, and simple logistics.

Stories:
- As a traveler, I want a 5–7 day plan built around my interests and budget.
- As a traveler, I want to browse restaurants/hotels and add favorites to a cart.
- As a traveler, I want to see itinerary locations on an interactive map.

============================================================
7. CORE USE CASES
============================================================
- Generate Itinerary: Submit details (destination, dates, interests, budget, group size)
  → AI returns structured plan → display and allow adjustments.
- Explore Options: Query transport/accommodation/restaurants → add selected items to cart.
- Manage Cart: View, update, or remove items; track budgets and summaries.
- Authenticate: Signup/login with secure credential handling; persist session token.

10. BACKEND DESIGN
============================================================
Modules:
- Controllers: auth, trip, itinerary, options, cart
- Services: aiService, mapsService, placesService, transportService, travelPlanService
- Middleware: auth (JWT), rate limiting, centralized error handler
- Routes: REST endpoints under /api (e.g., /api/auth, /api/trips, /api/itineraries)

AI Service Highlights:
- Prompt engineering to elicit strict JSON schema outputs.
- Robust parser: strip markdown fences and comments, remove trailing commas, map
  alternative keys (e.g., dailyActivities → dailyPlans).
- Correction pass to enforce dailyPlans length equals number of trip days.

- Cart: { userId, tripId, items[type, provider data, price], totals, timestamps }

12. API DESIGN (REPRESENTATIVE)
============================================================
Auth:
- POST /api/auth/signup → create user, return token
- POST /api/auth/login → authenticate, return token

Trips & Itineraries:
- GET/POST /api/trips; GET/PUT/DELETE /api/trips/{id}
- POST /api/itineraries/generate; GET /api/itineraries/{id}

Options & Cart:
- GET /api/options/{tripId}/transport|accommodation|restaurants
- POST/GET /api/cart/{tripId}; item subroutes for add/update/remove

15. AI PLANNING APPROACH (IDEA & METHOD)
============================================================
Idea:
- Use an LLM (Gemini) to generate structured local-expert itineraries, then enhance with
  external providers for transport/hotels/restaurants.

Method:
- Prompting: persona-driven with a strict JSON schema (summary, daily plans, recommendations,
  practical info). Includes destination, dates, interests, budget, and group size.
- Validation: Clean and parse JSON; validate schema; correct day count to match dates.
- Extensibility: Allow swapping models, adding retries, or integrating templates/caching.

============================================================
16. CACHING & PERFORMANCE
============================================================
- AI Response Cache: In-memory cache (TTL ~1 hour) keyed by destination/dates/interests/budget.
- Database: Index frequently queried fields; avoid large unbounded scans.
- Options: Batch or defer expensive external calls; cache results where appropriate.
- Frontend: Memoize heavy computations; code-splitting for faster loads.

============================================================
17. ERROR HANDLING & OBSERVABILITY
============================================================
- Centralized Express error middleware for consistent error payloads.
- Detailed logs around AI calls and parsing to diagnose malformed outputs.
- Graceful user-facing messages with actionable steps.

============================================================
18. SECURITY, PRIVACY & COMPLIANCE
============================================================
- JWT for authentication; bcrypt for password hashing.
- CORS configuration, rate limiting, and input validation.
- Secrets managed via environment variables; minimize PII in logs.
- Principle of least privilege for API keys; rotate regularly.

============================================================
19. DEPLOYMENT & ENVIRONMENT SETUP
============================================================
Backend:
- Node 18+; set MONGODB_URI, JWT_SECRET, GEMINI_API_KEY.
Frontend:
- Vite; set VITE_API_BASE_URL and optional VITE_API_PATH.
Run:
- Local: separate dev servers (frontend/backend). Production: containerize or deploy to PaaS.
